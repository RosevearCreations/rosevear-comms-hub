# QL-434 — Protected New-Ceremony Evidence Consumption, Independently Signed Authority Handoff & Original-Host Supervised Re-entry Readiness

## Release boundary

This change consumes the already protected QL-433 **non-activating new-ceremony precheck**, independently witnesses a new authority handoff, and records the original Windows host's readiness for a **separate** supervised QL-429/430 enrollment. It does **not** start or resume a receiver, turn on a gateway, call an activation API, claim universal CONNECTED, or verify real uptime. The success state explicitly retains **connection=HOLD**, **receiver=OFF_VERIFIED_SIGNED_READBACK**, **activationAuthorized=false** and **slaveGate=HOLD_NEXT_MASTER_INTEGRATION_STAGE**.

Only code, synthetic signed evidence tests and this operator handoff are installed. No external key custody, live anchor, production Windows receiver, background monitor, or remote signing service has been enrolled by this build.

## Required original-host process

1. Under an authenticated original-host protected session on **DESKTOP-AE894KC**, independently verify the previously signed QL-433 precheck and retrieve its durable one-use record. Match its incident/old scope/new ceremony IDs against the QL-432 owner-accepted one-use receipt and terminal QL-431 **RECONCILED** checkpoint. Reject a previous ceremony ID, different episode, digest mismatch, changed source/controller SHA, missing signature custody, receiver ON, or any browser-generated acceptance claim.
2. Generate a fresh, unique `authorityId` and `challengeNonce`. Prepare a redacted QL-434 export binding the exact original QL-431/432/433 chain digests, signed old source/controller revision, incident, next distinct ceremony and episode, original machine ID, and the restricted action `PREPARE_NEW_SUPERVISED_QL429_QL430_CEREMONY_NO_RECEIVER_ACTIVATION`. Export creation is **unsigned** and has no operational authority until the independent handoff is actually returned.
3. A separately protected authority **issuer** must sign the exact QL-434 export and nonce using an independently pinned Ed25519 key. A second independent **witness** must sign a fresh readback of the issuer signature digest, export digest, nonce and next-ceremony IDs using a **different** pinned key. Both must bind their statements to `NEW_CEREMONY_READINESS_HANDOFF_NOT_ACTIVATION` and `INDEPENDENT_HANDOFF_READBACK_NO_ACTIVATION`, respectively. A mock GitHub CI provider is not an actual external signer.
4. **DESKTOP-AE894KC** must freshly attest to receiver `OFF`, exact next ceremony/episode and exact source/controller commit revisions, original incident and signed witness digest. Its signed readiness is only `HOST_READY_FOR_SEPARATE_NEW_SUPERVISED_CEREMONY_ONLY`.
5. A **separately pinned independent receiver** must observe and sign fresh `OFF` after the original-host statement, referring to the exact host-readiness and independent witness digests. No host-only OFF statement is sufficient.
6. Collect independently signed, fresh and different recovery-readiness reports from **rosevear-ai-hub, rosevear-comms-hub and ai-data-platform**. Each must match the same original incident and scope, QL-433 receipt, signed authority-witness digest, receiver-OFF digest and next ceremony/episode. All must say `NEW_CEREMONY_PREPARATION_ONLY_NOT_ACTIVATED`.
7. Original owner and independent reviewer must each sign `AUTHORIZE_NEW_CEREMONY_READINESS_ONLY_RECEIVER_OFF_NO_ACTIVATION`, bound to all the same evidence and the ordered three-Master receipt digest.
8. Just before saving, reopen and verify the original QL-431, QL-432 and QL-433 private receipts again. Consume a **one-use** QL-434 receipt under a protected absolute filesystem directory, exclusive `wx` create, fsync file + directory, restrictive permissions, and exact local readback. A second incident claim, forged signature, missing trusted pin, unreadable ledger, mutated predecessor record, stale observation or attempted ON/activation fails closed.
9. The only accepted state is `DURABLE_QL434_SIGNED_NEW_CEREMONY_READINESS_HANDOFF` with connection HOLD and `activationAuthorized=false`. A **new** QL-429/430 owner-supervised ceremony and separately verified runtime activation evidence is still required before any future CONNECTED status. This routine never exposes or invokes receiver activation methods.

## Automated checks

Positive tests assert exact signed handoff, signed original-host OFF, independent receiver OFF, three-Master signatures, dual-owner review, durable one-use receipt, and no calls to activation. Negative tests reject missing original-host authority; forged issuer/witness, stale evidence, mismatched nonce and scope; TEMPLAR host and original-host ON; forged or stale independent receiver; missing/duplicated/forged Master reports; unauthorized activation action or forged owner/reviewer; wrong QL-431/432/433 custody; tampered local receipt and replay. These remain simulated tests. Gate on the protected evidence workflow, app build and Windows owner-key tests on both PR candidates and the exact production `main` commit, plus production public Worker JS/CSS SHA-256 parity.

**Limitations:** The local ledger can still be destroyed by a privileged actor. Deployment of a truly independent authority issuer, original-host signer and external immutability is a separate supervised operational step; neither the simulated test provider nor GitHub release proves this. Signed evidence does not by itself turn on the receiver.
