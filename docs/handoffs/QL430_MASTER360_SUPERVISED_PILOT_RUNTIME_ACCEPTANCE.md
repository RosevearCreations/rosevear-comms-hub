# QL-430 — Original-Host Supervised Pilot Re-entry Ceremony, Independent Receiver State Attestation & Three-Master Runtime Acceptance

## Delivered capability and critical status boundary

QL-430 wires QL-429's signed original-host re-entry witness to the existing QL-424 one-test activation and QL-423 signed source-replay authority; it then independently verifies a **second** signed receiver runtime attestation, QL-424's three-Master operational acceptance, a separate three-Master QL-430 attestation batch, distinct dual-owner acceptance and durable one-use incident custody.

The implementation is protected Node-only and is NOT scheduled, wired to a live Windows service, connected to an external signer, or supplied with actual private keys. **The release proves code/test integrity, not a real QL-430 pilot, not a live CONNECTED state, and not an uptime SLA.** Production remains connection HOLD until actual original-host signed runtime evidence exists and is independently verified.

## Protected original-host supervised procedure

1. Independently verify the QL-429 off-host enrollment, signed challenge, three signed Master witnesses, and dual-owner precheck on original Windows host DESKTOP-AE894KC. Load the private QL-429 enrollment ledger and original host signed challenge response. The prior receiver must be OFF. Use the independently pinned enrolled original-host signer.
2. Enroll a *new* independently approved QL-424 original-host signer and obtain a *new* signed QL-423 protected custody/replay restoration, source/controller revisions and exact new episode. The new QL-424 ceremony must equal QL-429's proposed nextCeremonyId, differ from the prior ceremony, and reference a different episode. The source and controller commit revisions must remain exact. Neither QL-429 witness nor a client-side flag alone is authorization.
3. Obtain a fresh separately dual-Ed25519-signed QL-430 operator authorization referencing the immutable QL-429 witness record digest, challenge digest, new QL-424 activation payload digest and action EXECUTE_NEW_SUPERVISED_QL424_ISOLATED_ONE_TEST. The original-host backend must have independently verified owner/reviewer custody, QL-424 enrollment, QL-429 witnesses and physical operator session.
4. Invoke runQl430SupervisedPilotReentry *only* in an authorized private backend, supplying the QL-424 ceremony/replay inputs, the real original-host protected receiver adapter, a second independently pinned read-only receiver attestation source and an authenticated three-Master evidence source. QL-430 fsyncs a **one-use ATTEMPT record before the enableOneTest call**, forbidding an interrupted or failed attempt from silently replaying the same ceremony.
5. The existing QL-424 runner checks the new dual-signed activation, three-Master signed QL-423 replay and original host enrolled signer, invokes exactly one protected ISOLATED_ONE_TEST enable, and independently verifies its original signed receiver runtime state. QL-430 then obtains a **separate** signed QL-430 receiver ON attestation bound to the same episode, source/controller revisions, QL-429 witness digest and original challenge ID. It must be freshly observed no earlier than QL-424's signed state. Its independent signer public key must differ from the QL-424 receiver signer.
6. The QL-424 verifier must then accept three separate signed live Master reports and dual owner signoff for that *new* ceremony. QL-430 requires **another** three signed Master reports bound to the QL-424 acceptance digest, fresh independent receiver digest and QL-429 witness record. Distinct owner/reviewer must sign the final exact ordered Master digest with action ACCEPT_FRESH_ISOLATED_PILOT_ONLY_KEEP_SLAVE_GATE_HOLD.
7. If any post-enable runtime attestation, Master acceptance, owner signature, or durable receipt fails, QL-430 requests protected fail-closed receiver disable. A verified disabled acknowledgement without a new independent signed OFF readback is conservatively labeled OFF_NOT_INDEPENDENTLY_RECHECKED. An unconfirmed disable or failed rollback is UNKNOWN_MANUAL_OPERATOR_RECOVERY_REQUIRED, and a new ceremony and independent shutdown verification are required. Failed attempts are never replayable.
8. Only after durable signed acceptance is committed and reopened may a protected runtime result declare VERIFIED_CONNECTED_PILOT for **that one isolated test**, with receiver ISOLATED_ONE_TEST_ON and slave gate HOLD_NEXT_MASTER_INTEGRATION_STAGE. It does **not** declare universal CONNECTED, measured uptime, production receiver availability or authorize the other application connections. Subsequent operational continuity requires QL-425/426 fresh signed heartbeats and fail-closed health monitoring.

## Delivery and testing limitations

CI regression runs all QL-417–430 protected evidence tests; QL-430 tests use synthetic Ed25519 keys and a mock receiver with no external side effects. Positive path covers QL-423/424 signed replay, original host challenge, new isolated ceremony, fresh independent receiver state, distinct three-Master/owner runtime signatures and durable acceptance. Negative coverage includes missing owner protection, wrong or replayed ceremony, forged independent readback, receiver OFF/stale evidence, duplicate/missing Masters, forged owner acceptance, automatic receiver disable, failed rollback UNKNOWN and one-use attempt replay.

Physical re-entry remains owner-supervised. External anchor operator enrollment, real Windows adapter/signers, scheduled continuous health and actual independent live proof are NOT configured or executed by GitHub release. Local ledger digests should be externally anchored against privileged host deletion; this build does not itself provide a remote immutable store.
