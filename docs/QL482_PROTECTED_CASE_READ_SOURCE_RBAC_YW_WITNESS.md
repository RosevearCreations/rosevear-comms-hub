# QL-482 — Protected private case-read API, exact source RBAC, first Yard Workers witness gate

## Release purpose and limits

QL-481 retained a file-only structural review in the authenticated owner portal. QL-482 adds a **runnable private Node HTTPS read endpoint** backed by the QL-480 signature-verified, hash-chained durable private journal. Its route is **not** published on Cloudflare, Vercel, Supabase, or the static owner portal. The Cloudflare Worker remains unchanged, and imported browser JSON is not trusted as a server reading.

The new module \`runtimes/master-telemetry/ql482-protected-case-read.mjs\` exports \`createQl482ProtectedCaseReader\`, \`createQl482HttpsServer\`, and \`verifyQl482YardWorkersLifecycle\`. It has no automatic listener. An operator may intentionally compose the module with their own provisioned QL-480 private adapter and authenticated private TLS deployment; no real endpoints, credentials or permissions are generated by this release.

## Private server contract

- Route: \`POST /internal/comms/ql482/cases/read\` on an **explicitly launched private HTTPS listener**, TLS 1.3, required trusted client certificate. Only \`application/json\`, body <= 4096 bytes, with **exactly** \`{"operatorReadPacket":{"payload":{...QL480 signed read...},"signature":"..."}}\`.
- The caller certificate's SHA-256 fingerprint must be explicitly enrolled, matching a single \`operatorId\`, role \`case-reader\`, and exact triples \`{sourceApp,environment,tenantId}\`. Source \`yard-workers\` does **not** grant \`icamp\`, and a tenant never grants another tenant.
- The operator read must carry a valid Ed25519 signature from the independently pinned QL-480 operator key, with exact schema, fresh timestamp and unique request ID; expired, unsigned, replayed, foreign-source and missing cases fail closed. No wildcard grants; no anonymous or browser-Supabase identity substitute.
- The server obtains case data solely from the QL-480 read method, which verifies source/operator signatures and durable digest chain. Response includes only redacted operational case state, source/tenant/episode, technical recovery and digest proof, with explicit \`productionAcceptance:false\`, \`sourceRuntimeVerified:false\`, \`authorityTransfer:false\` and \`NOT_SENT\`.
- This endpoint is **read only**. No \`ingest\`, \`command\`, provider send, account modification, scheduled start, or customer records are exposed.

## First Yard Workers incident verification

\`verifyQl482YardWorkersLifecycle\` reconciles a final CLOSED Yard Workers journal against an independently signed Ed25519 reviewer packet from a **different pin** than source/operator. It checks the same source/tenant/episode, case ID, source revision, final sequence, source receipt and journal hash, technical recovery and separately signed operator closure. Tampered signatures, foreign tenants, changed receipts, incorrect order or premature closure fail.

The independent reviewer packet is deliberately constrained to \`originalHostObserved:false\`; the local/synthetic proof **never** equates to real Yard Workers enrollment. In production, the first actual case remains **HOLD** until independent, original-host source/tenant/signer enrollment, a genuine missing heartbeat and recovery observed from Yard Workers, operator closure, and separate witness readback can be verified. The protected source must be deployed and the original owner must explicitly choose to start the private server. The known QL-481 HOLD may not be silently promoted.

## Safe integration example (server not automatically started)

\`\`\`js
import {createQl480PrivateCaseAdapter} from './ql480-scoped-incident-adapter.mjs';
import {createQl482ProtectedCaseReader,createQl482HttpsServer} from './ql482-protected-case-read.mjs';
// Material read at runtime from restricted original-host files, never git.
// sourcePins includes independently enrolled Yard Workers and iCamp pins.
const adapter=createQl480PrivateCaseAdapter({directory,sourcePins,operatorPin,
  environment:'PRIVATE_STAGING'});
const reader=createQl482ProtectedCaseReader({adapter,operatorPin,acl:{
  [trustedClientCertificateSha256]:{operatorId:'enrolled-operator',role:'case-reader',
   scopes:[{sourceApp:'yard-workers',environment:'PRIVATE_STAGING',tenantId:'authorized-tenant'}]}
}});
const server=createQl482HttpsServer({tlsOptions:{key,cert,ca},reader});
// Explicit, supervised original-host loopback launch only after enrollment:
// server.listen(8842,'127.0.0.1');
\`\`\`

The TLS private key, CA, operator signer pin, certificate fingerprint and exact tenant authority must originate from authentic private provisioning. Do not copy values from this document into a real enrollment. No restart is needed for Cloudflare. A manually launched private Node server must be intentionally restarted when its deployed runtime code changes; this build doesn't install one.

## Release acceptance

Automated tests use temporary independent Ed25519 identities and an isolated nonproduction QL-480 journal, proving a real durable **synthetic** missing → recovered → independently reviewed closed cycle, tenant-specific RBAC denial, signature, replay and tamper protections, and read-only response. Tests can certify code, not external Yard Workers or an original Windows host.

Next proposed: **QL-483 — Original Yard Workers private signer enrollment, real source-to-operator incident witness and safely authenticated UI readback**, contingent on genuine authority and connectivity. Reuse rather than replace QL-482 server controls.
