# QL-355 — Independent original issuer, dual-owner enrollment and first private TEST acceptance

## Release versus live activation

QL-355 contains **server-only** Ed25519 verification for two independently pinned
external authorities, the existing QL-354 dual-owner single-use enrollment permit,
and a strict read-only first TEST acceptance gate. Synthetic regression fixtures
prove the cryptographic flow; they are **not original issuer evidence**.

The original issuer and separate field witness must provide **genuinely signed**
attestations over the same exact 64-character QL-340B enrollment payload SHA-256.
The original pinned identities, their revocation state and their custody must be
confirmed by a service or human process independent of the request, signers and
GitHub checkout. No code in this repository can self-create that trust.

**Do not treat CI GREEN, a successful TLS handshake, an HTTP 503, an owner-created
public key, a JSON `approved: true`, or two matching screenshots as enrollment.**
`main` GREEN means the *software* passed production checks. The first actual
connection remains **DISCONNECTED / HOLD** until the original hosts and external
authorities satisfy every gate below.

### 3. Independent issuer and witness, before owner signatures

An independently authenticated original software issuer and a **different**
field witness review original Windows process provenance, original certificate
chain, Tailnet ACL and rollback evidence, with four byte-exact witness hashes.
Each separately signs the following canonical payload using its own original
private Ed25519 key; those keys are **not generated by this build**:

```json
{
  "schema": "rosevear.hub.ql355.independent-authority-signature.v1",
  "role": "original_issuer",
  "audience": "rosevear-comms-hub:original-enrollment:TEST",
  "enrollmentPayloadSha256": "<the exact reviewed 64-character digest>",
  "scope": "one-original-device-test-only",
  "issuedAt": "<UTC ISO 8601>",
  "expiresAt": "<UTC ISO 8601 within 20 minutes>"
}
```

The second party sets `role` to `field_witness`. The outer signed record uses
`{ "schema": "rosevear.hub.ql355.independent-authority-signature.v1",
"payload": { ... }, "signature": "<base64url Ed25519 signature>" }`.
The independent private verifier supplies **separately pre-approved** pinned
issuer/witness SPKI keys and independent custody/revocation verification. It
rejects signer keys supplied by the request itself, altered payload bytes,
expired attestations, reused owner keys, and unapproved self-attestations.

If a real issuer cannot sign, **stop and leave HOLD**. Do not substitute a newly
created signer, a copied PEM, or a purported issuer identity we invent.

`acceptQl355FirstPrivateTest` independently requires:

- the original authenticated operator session, unexpired and not revoked;
- the actual verified original Tailnet TLS path and loopback receiver;
- the original device Ed25519 signature over the exact challenge;
- one and only one matching receipt queried as the limited receiver DB role;
- all six application peers still disconnected, with no customer actions.

**Stop the supervised receiver after the one-device TEST** and preserve its
receipt for read-only verification. A successful first TEST still never grants
