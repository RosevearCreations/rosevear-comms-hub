## Cross-build safety and release rules

- **ACK Delivery Evidence:** `UNDER_REVIEW / PARKED_FOR_LATER` throughout QL-290–304. It is **not** a HELD item and is **not** included for implementation in this active batch. Resuming it requires a separate owner instruction.
- **Six integrations:** `DISCONNECTED / HOLD`. Original signed Proof-B, independently authenticated issuer/reviewer/custodian/witness, allowed nonproduction tenant, scoped GET identity and explicit owner **TEST-only** approval must be genuinely verified before any private source gateway experiment. A public GitHub HTTP 200 or a local case string is not independent proof.
- **No live communications:** calls, SMS/MMS, email sends, IVR, provider callbacks, call recording, AI auto-send, dispatch, payment, real customer reads/writes and real owner approvals remain disabled. Synthetic fixtures are not actual customer evidence.
- **No unreviewed persistence:** use existing reviewed local preference storage only for allowed layout settings; do not silently introduce private data into localStorage, a database, telemetry or exports.
- **One guarded release per build:** focused tests, full app tests, security baseline, production build, exact feature→`dev`→`main` Git tree, and five successful checks on the **exact `main` commit**. Confirm the public Worker serves the same JS/CSS bytes before announcing **Production GREEN**. Record the release SHA and next queue status after completion.
